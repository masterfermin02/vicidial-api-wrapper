# Changelog

All notable changes to the Vicidial API Wrapper will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- `...Response()` variants for the 23 `Agent` methods that lacked one (`pauseCode`, `logout`, `recording`, `parkCall`, `transferConference`, ...). Every Agent and Admin function now has both a string and a `VicidialResponse` variant; `AgentResponseVariantsTest` enforces it.
- Typed parameter objects `VicidialApi\Parameters\{DialParameters, DispoParameters, AddLeadParameters, UpdateLeadParameters}`; `dial()`, `dispo()`, `addLead()` and `updateLead()` accept them in place of an array. `with()` adds unmodelled parameters such as custom list fields.
- `Agent::dial()` accepts `lead_id` without a `phone_number`, as documented for `external_dial`.
- `Agent::UPDATE_FIELDS_ALLOWED` public constant.
- `VicidialResponse::fields()` (positional values without the message text), `message()`, `rows()` and `columns()` (multi-line pipe / CSV / tab reports, keyed by header when `header=YES` was sent or a header line is detected), `statusCode()`, `headers()` and `header()` (raw HTTP layer). `from()` takes the HTTP status code and a header hint; `HttpTransporter` passes both.
- `stage=json` bodies are decoded (objects via `get()`, lists via `rows()`); previously they fell into the `key: value` branch.
- `Payload::parameter()` accessor.
- `tests/Contract/RetryStatusCodeTest` covering status-code retries for throwing and non-throwing clients; `MockPsrClient` accepts queued `Throwable`s.
- **Laravel integration**: `VicidialApi\Laravel\VicidialServiceProvider` (auto-discovered via `extra.laravel`), `VicidialApi\Laravel\Facades\Vicidial`, publishable `config/vicidial.php` (`php artisan vendor:publish --tag=vicidial-config`), `php artisan vicidial:ping`. Bind a PSR-18 client as `vicidial.http_client` to override the HTTP client. See `docs/LARAVEL.md`.
- `VicidialConfig::fromArray()` builds a configuration from a config-file shaped array (used by the provider, works without Laravel). `VicidialConfig::DEFAULT_USER_AGENT`.
- `VicidialApi\Diagnostics\Ping` / `PingReport` / `EndpointCheck`: framework-free connectivity and permission check that probes both APIs and explains failures in plain language.
- `tests/Fixtures/official/responses.json`: every example response from the official docs (722 for 89 functions), generated by `scripts/scrape-official-responses.py`; `OfficialResponsesTest` parses all of them.
- `scripts/check-api-parity.php` and the weekly `.github/workflows/api-parity.yml` that opens an issue when the official docs list a function the wrapper lacks.
- README "Click-to-dial in 10 lines" quick start; `docs/LARAVEL.md`; `scripts/README.md`.
- Idempotency guidance for retries (`RetryConfig` docblock, `docs/RELIABILITY_FEATURES.md`, quick reference, README): VICIdial has no idempotency keys, so network-error retries of `add_lead` can insert duplicates.
- GitHub Actions CI (`.github/workflows/ci.yml`) running pint, rector, phpstan and phpunit on PHP 8.2, 8.3 and 8.4.
- `docs/README.md` documentation index.

### Fixed
- **5xx responses were never retried.** `HttpTransporter` only inspected Guzzle's `ClientException` (4xx); a 5xx arrives as `ServerException` and was thrown as `TransportException` on the first attempt. It now inspects `BadResponseException` (both), and a PSR-18 client that returns an error response without throwing is retried on the status code too.
- `RetryException` is now thrown when retries are exhausted (the code path was unreachable: the last attempt always threw `TransportException`). A failure on the first attempt that is not retryable still throws `TransportException`.

### Changed
- `VicidialResponse` reports `error` (so `ok()` is false) for an empty body, an HTML body (`text/html` content type or `<!DOCTYPE` / `<html` start) and for HTTP status 400+ without a `SUCCESS:` prefix. These are proxy / web-server answers, never VICIdial output, and used to read as success.
- `VicidialResponse::toArray()` includes `statusCode` and `headers`.
- Default `User-Agent` is `VicidialApi-PHP-Wrapper/4.2`.
- Dev dependencies: `illuminate/support`, `illuminate/console`, `illuminate/config` (`^11|^12`) added for the Laravel integration tests; `nunomaduro/collision` removed; `symfony/var-dumper` allows `^7.0`; phpstan runs with `--memory-limit=512M`. Runtime dependencies are unchanged (`illuminate/support` is only suggested).
- `Agent::dial()` and `Agent::updateFields()` throw `VicidialApi\Exceptions\InvalidArgumentException` (a `VicidialException`) instead of a bare `\Exception`. The stale `@deprecated` tag on that class was removed.
- `Agent::updateFields()` allow-list re-synced with AGENT_API.txt (2025-08-30): the `formreload`, `scriptreload`, `script2reload`, `emailreload` and `chatreload` triggers are accepted.
- Default `source` query parameter is `vicidial-api-wrapper` instead of `test` (`VicidialConfig::DEFAULT_SOURCE`). It is a free-text label that shows up in VICIdial logs; set `source:` explicitly if you depended on `test`.
- `AgentContract` gained the new `...Response()` methods and `AdminContract::addLead()` / `updateLead()` accept the typed parameter objects. Custom implementations of these interfaces must add the methods.
- Repository root decluttered: `METHOD_NAMING_CONVENTIONS.md`, `QUICKSTART.md`, `RELIABILITY_FEATURES.md` and `RELIABILITY_QUICK_REFERENCE.md` moved to `docs/`; implementation summaries moved to `docs/archive/`. All links updated.
- `docs/response-dto.md` merged into `docs/RESPONSE_DTO.md`.

## [4.1.0] - 2026-10-12

### Added
- **Full Non-Agent API parity** with `NON-AGENT_API.txt` (vicidial.org, updated 2026-09-25). New `Admin` methods, each with a `...Response()` DTO variant:
  `soundsList`, `batchUpdateLead`, `agentInGroupAvailability`, `leadAllInfo`, `leadSearch`, `copyDid`, `deleteDncPhone`, `deleteFpgPhone`, `hopperBulkInsert`, `updateAltUrl`, `updatePresets`, `leadDearchive`, `updateRemoteAgent`, `userDetails`, `copyPhone`.
- **Full Agent API parity** with `AGENT_API.txt` (updated 2025-08-30). New `Agent` methods with DTO variants: `stereoRecording`, `sendNotification`, `refreshPanel`.
- Coverage guard tests (`AdminCoverageTest`, `AgentCoverageTest`) that fail when a documented Vicidial function has no wrapper method.
- `tests/Fakers/RecordingTransporter` to assert on the exact URL and query string a resource method produces.
- `docs/VICIDIAL_API_GUIDE.md`: how the Vicidial Agent and Non-Agent APIs work (endpoints, auth, permissions, response formats, limits) and how this wrapper maps onto them.
- `docs/ROADMAP.md`: audit findings and prioritized improvement plan.
- graphify knowledge graph of the codebase (`graphify-out/`) and a `CLAUDE.md` section so AI assistants query the graph before answering codebase questions.

### Fixed
- **`TransportException` could not be autoloaded.** The class lived in `TransporterException.php`, so any network error (timeout, DNS failure, connection refused) crashed with "Class not found" instead of throwing `TransportException`. The class now lives in `TransportException.php`; `TransporterException` remains as a deprecated alias.
- **`VicidialApi::createWithBasicAuth()` was not static** although the README documents it as a static call, which failed with "Non-static method cannot be called statically".
- **Double URL-encoding in `Agent` methods.** Values were passed through `urlencode()` and then `http_build_query()`, so `+` became `%252B` and spaces became `%2B`. Values are now encoded exactly once.
- **`Agent::switchLead()` sent the lead as `value`**, which the Agent API ignores (it reads `lead_id` or `vendor_lead_code`), so the call always failed with "switch_lead not valid". It now sends `lead_id`.
- Request URLs no longer contain a double slash between the host and the script path (`http://host//agc/api.php`).
- Removed leftover "OpenAI" wording from `Factory` and `VicidialApi` docblocks.

### Deprecated
- Default `User-Agent` bumped to `VicidialApi-PHP-Wrapper/4.1`.
- `VicidialConfig` option `urlEncodeDefault` / `isUrlEncodeDefault()`: a no-op since v3.0.0. Values are always encoded exactly once by the transport. README Example 5 (`withUrlEncode(true)`) referred to a method that no longer exists and has been rewritten.

## [2.0.0] - 2026-01-26

### Added - Major Features

#### Reliability Features 🛡️
- **Configurable Timeouts**: Separate connect timeout (default: 10s) and request timeout (default: 30s)
  - `VicidialConfig::create(..., timeout: 60, connectTimeout: 10)`
  - Prevents hung requests and improves resilience
  
- **Automatic Retries with Exponential Backoff**: Handle transient failures gracefully
  - New `RetryConfig` value object for retry configuration
  - `RetryConfig::default()` - 3 attempts with exponential backoff
  - `RetryConfig::custom()` - Full customization
  - `RetryConfig::disabled()` - Explicit opt-out
  - Retries 5xx errors, 429 rate limits, and network failures
  - Exponential backoff with jitter (prevents thundering herd)
  - Per-attempt logging for observability
  
- **PSR-3 Logger Integration**: Pluggable logging for production observability
  - Added `psr/log:^3.0` dependency
  - `NullLogger` included for no-op behavior (default)
  - Automatic sensitive data redaction (passwords, API keys, etc.)
  - Comprehensive logging at DEBUG, INFO, WARNING, ERROR levels
  - Request metrics: duration, status codes, retry attempts
  - Sanitized parameter logging for security

#### Configuration System Enhancements
- Enhanced `VicidialConfig` with new parameters:
  - `connectTimeout` - Connection establishment timeout
  - `retryConfig` - Retry behavior configuration
  - `logger` - PSR-3 compatible logger instance
- Validation ensures connect timeout ≤ request timeout

#### Method Naming Conventions
- All methods use consistent **camelCase** naming
- Clear mapping from legacy Vicidial API snake_case functions
- Examples: `updateFields()`, `pauseCode()`, `mohList()`, `addLead()`
- Response DTO variants follow same convention with `Response` suffix

## Migration Guide

### From v1.x to v2.0

#### No Breaking Changes ✅
All v1.x code continues to work in v2.0 without modifications.

#### Recommended Upgrades

**Add Reliability Features** (opt-in):
```php
// Before (v1.x)
$client = VicidialApi::create($host, $user, $pass);

// After (v2.0 with reliability)
use VicidialApi\VicidialConfig;
use VicidialApi\VicidialClient;
use VicidialApi\ValueObjects\RetryConfig;

$config = VicidialConfig::create(
    host: $host,
    user: $user,
    pass: $pass,
    protocol: 'https',
    timeout: 60,
    connectTimeout: 10,
    retryConfig: RetryConfig::default(),
    logger: $logger,
);

$client = VicidialClient::make($config);
```

**Adopt Response DTOs** (opt-in):
```php
// Before (string parsing)
$result = $client->agent()->updateFields($agent, $fields);
if (strpos($result, 'SUCCESS') !== false) {
    // parse result manually
}

// After (structured response)
$response = $client->agent()->updateFieldsResponse($agent, $fields);
if ($response->ok()) {
    $leadId = $response->get('lead_id');
}
```

## Upgrade Recommendations

### For Development
- Use `VicidialConfig` and `VicidialClient` (modern API)
- Adopt Response DTOs for structured data access
- Enable retries with `RetryConfig::default()`

### For Production
- ✅ **Must**: Set explicit timeouts (`timeout: 60, connectTimeout: 10`)
- ✅ **Must**: Enable logging with PSR-3 logger
- ✅ **Recommended**: Enable retries (`RetryConfig::default()`)
- ✅ **Recommended**: Use HTTPS (`protocol: 'https'`)
- ✅ **Recommended**: Use Response DTOs for better error handling

### Minimal Production Configuration
```php
use Monolog\Logger;
use Monolog\Handler\StreamHandler;
use VicidialApi\VicidialConfig;
use VicidialApi\VicidialClient;
use VicidialApi\ValueObjects\RetryConfig;

$logger = new Logger('vicidial-api');
$logger->pushHandler(new StreamHandler('logs/vicidial.log', Logger::DEBUG));

$config = VicidialConfig::create(
    host: getenv('VICIDIAL_HOST'),
    user: getenv('VICIDIAL_USER'),
    pass: getenv('VICIDIAL_PASS'),
    protocol: 'https',
    timeout: 60,
    connectTimeout: 10,
    retryConfig: RetryConfig::default(),
    logger: $logger,
);

$client = VicidialClient::make($config);
```
